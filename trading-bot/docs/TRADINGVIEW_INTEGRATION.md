# TRADINGVIEW INTEGRATION (Phase 22J)

What Mr. Cash can and cannot do with TradingView, stated plainly. This document
exists mainly to be honest about a limitation, because the alternative — quietly
implying a live integration that does not exist — would be the kind of thing
this project is built to avoid.

---

## 1. The limitation, up front

**TradingView provides no public, supported API that lets external software draw
on, or stream data into, a user's logged-in chart.**

Specifically:

- **Pine Script runs inside TradingView**, on TradingView-provided data. It
  cannot make an HTTP request, cannot read a file, and cannot fetch a URL. There
  is no `fetch()` in Pine, by design.
- There is **no supported "draw on my chart" endpoint**. The charting REST/UDF
  interfaces are for *supplying price data to a chart library you host yourself*,
  not for annotating tradingview.com.
- The **Charting Library / Advanced Charts** product (a self-hosted widget) does
  expose a drawing API — but that is *your own embedded chart*, not the
  tradingview.com chart you are logged into.

### What we will not do about it

- We do **not** scrape TradingView.
- We do **not** automate or drive a logged-in TradingView session.
- We do **not** ship a browser extension that injects drawings.

Any of those would violate TradingView's terms, break without warning, and put a
user's account at risk. If a supported mechanism ever appears, it would be a
separate, explicitly designed and validated integration — not a workaround
smuggled in here.

---

## 2. What we do instead: a Pine snapshot export

`GET /api/intel/export/pine` generates **self-contained Pine v5 source** in
which Mr. Cash's real annotations are **baked in as constants** (fixed bar times
and prices). You paste it into the Pine Editor and add it to your chart.

Generated by `src/intel/pine.ts` from the **same canonical annotations** the
native chart draws — so the two cannot silently diverge. There is no
reimplementation of the ICT rules in Pine, and therefore no second calculation
that could drift from the engine.

### What it draws

| Concept | Pine form |
|---|---|
| Previous day / week high & low | dashed `line.new` + label |
| Session highs & lows | dashed line + label |
| Equal highs / equal lows | dashed line + label |
| Swing points (H/L, HH/HL/LH/LL) | `label.new` |
| BOS / CHoCH | `label.new` |
| Fair value gaps (bullish / bearish) | `box.new` |
| Order blocks, breaker blocks | `box.new` |
| ICT setups (silver bullet, unicorn, turtle soup) | `label.new` |
| Liquidity sweeps / raids / failed breakouts | `label.new` |
| Entry, stop, target | `line.new` + label |
| Trend / range regime markers | `label.new` |

Each layer gets an `input.bool` toggle, so groups can be switched off inside
TradingView too. Data quality travels into the label text: an `APPROXIMATE`
reading is visibly marked as such there as well.

### What it does NOT do

- **It is not live.** It is a point-in-time snapshot, stamped with the generation
  time and engine version in the file header. To refresh it, re-export and paste
  again.
- **It carries no provenance inspector.** TradingView has no equivalent of the
  native chart's "why is this on my chart?" panel, so provenance is compressed
  into label text. The full record stays in Mr. Cash.
- **It is capped.** TradingView limits boxes, labels and lines per script
  (`max_boxes_count` etc.), and the export applies its own cap
  (`config.intelligence.maxPineDrawings`, default 400). Anything not drawn is
  reported in `skipped` with the reason — never dropped silently.
- **Bar alignment is your responsibility.** Set the chart to the same symbol,
  timeframe and exchange listing, or the baked times will land on the wrong bars.

---

## 3. Security

The export is text a user pastes into a third-party website, so everything that
reaches the output passes `sanitisePineText`, which strips:

- `api_key` / `secret` / `token` / `password` / `pin` / `csrf` / `bearer` assignments
- long hex and base64 runs (the shape keys and hashes take)
- `$ENV_VAR`, `process.env.*`, `MRCASH_*`, `EXCHANGE_API_*`, `ANTHROPIC_API_KEY`
- absolute-looking filesystem paths
- URLs containing credentials

Quotes, backslashes and newlines are neutralised so nothing can break out of a
Pine string literal. The filename is reduced to `[a-z0-9._-]`, so a symbol like
`BTC/USDT` cannot contribute a path separator.

Tests (`test/intel/pine.test.ts`) feed a deliberately poisoned rationale
containing a fake key, a path and a token, and assert that none of them appears
in the generated file. **No account information, balance or credential is ever
included** — the export contains only symbol, timeframe, times, prices and labels.

---

## 4. The inbound direction (unchanged)

TradingView → Mr. Cash already works and is untouched by this phase:
`POST /api/tv-alert` accepts a TradingView webhook alert, authenticated by
`config.tradingview.webhookSecret`. That remains the only inbound integration.

---

## 5. Architecture

```
MR. CASH ENGINE
      ↓
canonical annotations  (src/intel/types.ts)
      ↓                            ↓
native Mr. Cash chart       Pine snapshot export
(real-time, authoritative)  (point-in-time artifact)
```

**The native chart is the real-time source of truth.** The Pine export is a
convenience for looking at the same marks inside TradingView, accepting that it
is a snapshot.

## 6. Summary table

| Capability | Supported? | Notes |
|---|---|---|
| Draw Mr. Cash levels on a TradingView chart | ✅ via pasted Pine | Snapshot, not live |
| Auto-refresh those levels as the market moves | ❌ | Pine cannot fetch external data |
| Push live data into a logged-in chart | ❌ | No supported API exists |
| Receive TradingView alerts in Mr. Cash | ✅ | `POST /api/tv-alert`, secret-protected |
| Read a user's TradingView account / drawings | ❌ | Not attempted |
| Scrape or automate a logged-in session | ❌ | Refused on principle |
